# 24CS2016 – Building Applications using Flutter

**Ex. No. 7 — Data Persistence using Google Cloud Firestore**
Reg No: URK23CS5015

## Aim

Develop a Flutter application that stores and retrieves employee or student information using Google Cloud Firestore, ensuring data persistence even after the application is closed and reopened.

## Description

Cloud Firestore is a NoSQL document database hosted on Google Cloud; unlike SQLite it persists data on a remote server rather than on the device, so records survive not only app restarts but also reinstallation, and can be shared across devices and users. The `cloud_firestore` and `firebase_core` packages connect a Flutter app to a specific Firebase project through a FirebaseOptions object (apiKey, appId, projectId, etc.) that is normally generated by running `flutterfire configure` against a real project.

This development environment has no Firebase project or credentials of its own, so lib/firebase_options.dart ships with clearly-labelled placeholder values ('REPLACE_WITH_YOUR_API_KEY', ...) and a comment explaining that `flutterfire configure` must be run to replace it before the screen can reach a real backend. main.dart checks for that placeholder apiKey before calling Firebase.initializeApp; when it is detected, the app still renders the full UI but sets a firebaseReady flag to false instead of attempting a network call that would otherwise hang. PeopleRecordsScreen uses that flag to disable the 'Save to Firestore' button, show an orange banner telling the user to connect a real project, and display 'No data — connect Firestore to see records here' instead of a spinner or a crash. Once a real project is configured, firebaseReady becomes true, the banner disappears, and the same PeopleRepository.addPerson / watchPeople methods (add() and a snapshots() StreamBuilder on the 'people' collection) persist and live-stream employee/student records to and from Cloud Firestore with no further code changes.

## Run it

```bash
cd code
flutter pub get
flutter run -d chrome   # or an Android device/emulator
```
